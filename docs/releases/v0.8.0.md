baton sessions can show in the Claude desktop app, and using both at once no longer needs care.

## New

- **Show a session in the Claude desktop app.** Choose **Desktop app…** on a running session
  (under *Details*) or in *Recent sessions*, tick the accounts whose desktop app should list it
  in its Code tab, and choose **Apply**. Accounts left unticked do not list it.
  - For the account the app is signed in to, it shows after the app is quit completely (tray
    icon too) and opened again. Other accounts show it when you switch to them in the app.
  - The choice follows the session after `/clear` and when baton goes on in a copy by itself.
  - Nothing is uploaded. baton writes a small entry per account into the app's data folder
    (only its own entries are ever changed or removed). It gives the conversation a second name
    in your own Claude Code folder: a hard link to the same file, not a copy.
  - API-key, cloud-provider, gateway and long-lived-token accounts cannot be chosen.
  - From the command line: `baton desktop <id> [--show a,b] [--hide c]`.
- **Open in two places, handled for you.** When the desktop app, a terminal, VS Code or another
  baton session opens a conversation that baton is running, baton moves its session to a copy
  on the same account:
  - right away if Claude is idle, otherwise once the current response or question is done;
  - in the session's own permission mode;
  - with a Windows notification, while the session's row says where it is open.

  The other side goes on in the original. A switch to another account, and reopening a session
  that was cut off, also continue in a copy when the conversation is open elsewhere by then.
- **Any Claude Code on your PC.** baton uses the newest Claude Code that works with it (2.1.268
  or newer): the CLI wherever it is installed (native, WinGet, Scoop, npm, `PATH`) or the copy
  that comes with the desktop app.
  - *Settings → Advanced → Claude Code to use* lists every copy found, with its version or why it
    cannot be used. You can pick Automatic, the desktop app's copy, one copy, or a path.
  - If your pick cannot be used for now, baton uses another and says so.
  - *Update the CLI* updates an old Claude Code CLI.
  - `baton doctor` lists every copy and marks the one in use.
- **Office columns and filter.**
  - Drag the floor guide's and the panel's edges to resize them (double-click resets). baton
    remembers the widths.
  - Untick sessions or whole floors in the floor guide to hide them from the office.
- **Pictures in a session.** Help now says that Alt+V pastes a picture from the clipboard (left
  Alt on a Korean keyboard). `baton doctor` checks that Claude Code can read the clipboard.

## Changed

- **Bringing in a conversation that is still open elsewhere** now continues in a copy by itself
  instead of asking you to close it first. `baton resume <id>` does the same. If the conversation
  is already running in baton, it brings up that session's window instead of opening a second
  one; `--copy` still always leaves the original as it is.
- **Floor numbers.** When every conversation of a project has been deleted, its floor number
  goes to the next new project. A floor still in the building never moves.
- **No warning for a newer Claude Code.** baton no longer warns that Claude Code is newer than
  the version it was tested with.
- `baton config claude_path` refuses a path that is not a `claude.exe` (a `.cmd` or `.ps1`
  wrapper would break baton's careful stop).

## Fixed

- **An old Claude Code CLI blocked baton.** When the CLI was too old, baton refused to start even
  if the desktop app's own Claude Code was new enough. It now uses the one that works.
- **Clicking a notification did not bring up the session.** Now it brings that session's window
  to the front. If Windows does not allow that, the window flashes on the taskbar.
- **The office's right column in a small window.** It dropped below the office out of line. In a
  narrow window the panel (then the floor guide too) now opens over the office from a button.
- **A desktop conversation looked closed.** The desktop app keeps a Claude Code ready and uses it
  for the next conversation you open. If that came more than two minutes later, baton did not see
  the conversation as open. baton now checks the process itself.

## 한국어

baton 세션을 Claude 데스크톱 앱에도 보이게 할 수 있고, 둘을 함께 써도 신경 쓸 것이 없어졌습니다.

**새 기능**
- **Claude 데스크톱 앱에 세션 표시.** 실행 중인 세션(*자세히* 안)이나 *최근 세션*에서 **데스크톱 앱 표시…**를
  누르고, Code 탭 목록에 이 세션을 보여 줄 데스크톱 앱 계정을 체크한 뒤 **적용**을 누르세요. 체크하지 않은
  계정에서는 보이지 않습니다.
  - 앱에 로그인된 계정에서는 앱을 완전히 종료(트레이 아이콘에서도)했다가 다시 열면 보입니다. 다른 계정에서는
    앱에서 그 계정으로 바꾸면 보입니다.
  - `/clear` 뒤나 baton이 스스로 사본으로 이어 간 뒤에도 선택이 세션을 따라갑니다.
  - 아무것도 업로드되지 않습니다. baton은 앱의 데이터 폴더에 계정마다 작은 항목을 쓰고, 자기가 쓴 항목만
    바꾸거나 지웁니다. 대화에는 평소 Claude Code 폴더에 두 번째 이름이 생깁니다. 복사본이 아니라 같은 파일을
    가리키는 하드 링크입니다.
  - API 키, 클라우드 제공자, 게이트웨이, 장기 토큰으로 로그인하는 계정은 고를 수 없습니다.
  - 명령줄에서는 `baton desktop <id> [--show a,b] [--hide c]`.
- **두 곳에서 열려도 알아서 처리.** baton이 이어 가는 대화를 데스크톱 앱, 터미널, VS Code, 다른 baton
  세션에서 열면 baton은 같은 계정에서 사본으로 옮겨 이어 갑니다.
  - Claude가 쉬고 있으면 바로, 아니면 지금 응답이나 질문이 끝난 뒤에 옮깁니다.
  - 세션의 권한 모드는 그대로입니다.
  - Windows 알림으로 알리고, 세션 줄에 어디에서 열렸는지 나옵니다.

  다른 쪽은 원래 대화로 이어 갑니다. 다른 계정으로 전환할 때나 끊긴 세션을 다시 열 때도 그사이 대화가 다른
  곳에서 열려 있으면 사본으로 이어 갑니다.
- **PC에 있는 Claude Code 아무거나.** baton과 맞는 것(2.1.268 이상) 중 가장 새 Claude Code를 씁니다. 어디에
  설치했든(네이티브, WinGet, Scoop, npm, `PATH`) CLI든, 데스크톱 앱에 들어 있는 것이든 됩니다.
  - *설정 → 고급 설정 → 사용할 Claude Code*에 찾은 것이 모두 버전과 함께 나오고, 쓸 수 없는 것은 이유가
    나옵니다. 자동, 데스크톱 앱의 것, 특정 하나, 경로 중에서 고를 수 있습니다.
  - 고른 것을 지금 쓸 수 없으면 baton이 다른 것을 쓰고 그렇다고 알려 줍니다.
  - *CLI 업데이트*로 오래된 Claude Code CLI를 업데이트할 수 있습니다.
  - `baton doctor`가 찾은 것을 모두 보여 주고 쓰는 것에 표시합니다.
- **사무실 열 조절과 숨기기.**
  - 층 안내와 오른쪽 패널의 가장자리를 끌어 너비를 바꿀 수 있습니다(두 번 클릭하면 처음대로). baton이 너비를
    기억합니다.
  - 층 안내에서 세션이나 층 전체의 체크를 해제하면 사무실에서 숨깁니다.
- **세션에 사진 붙여넣기.** 도움말에 Alt+V로 클립보드의 사진을 붙여 넣는다는 안내가 생겼습니다(한국어
  키보드에서는 왼쪽 Alt). `baton doctor`가 Claude Code가 클립보드를 읽을 수 있는지 확인합니다.

**바뀐 점**
- **아직 다른 곳에서 열려 있는 대화를 가져오면** 먼저 닫으라고 하지 않고 알아서 사본으로 이어 갑니다.
  `baton resume <id>`도 같습니다. 이미 baton에서 실행 중인 대화면 두 번째 세션을 열지 않고 그 세션 창을
  앞으로 가져옵니다. `--copy`는 여전히 언제나 원래 대화를 그대로 둡니다.
- **층 번호.** 한 프로젝트의 대화가 모두 지워지면 그 층 번호는 다음 새 프로젝트가 씁니다. 건물에 남아 있는
  층은 옮겨지지 않습니다.
- **새 Claude Code 경고 없음.** Claude Code가 baton이 테스트한 버전보다 새것이라는 경고를 더는 하지 않습니다.
- `baton config claude_path`는 `claude.exe`가 아닌 경로를 받지 않습니다(`.cmd`나 `.ps1` 래퍼는 baton의
  안전한 종료를 깨뜨립니다).

**고친 점**
- **오래된 Claude Code CLI 때문에 baton을 쓸 수 없음.** CLI가 너무 오래되면 데스크톱 앱의 Claude Code가
  충분히 새것이어도 시작하지 않았습니다. 이제 쓸 수 있는 쪽을 씁니다.
- **알림을 눌러도 세션이 앞으로 나오지 않음.** 이제 그 세션 창을 맨 앞으로 가져옵니다. Windows가 허락하지
  않으면 작업 표시줄에서 창이 깜빡입니다.
- **작은 창에서 사무실 오른쪽 열.** 사무실 아래로 내려가 정렬이 맞지 않았습니다. 이제 좁은 창에서는 패널(더
  좁으면 층 안내도)이 위쪽 버튼을 누르면 사무실 위에 열립니다.
- **열려 있는 데스크톱 대화를 닫힌 것으로 봄.** 데스크톱 앱은 Claude Code를 미리 띄워 두었다가 다음에 여는
  대화에 씁니다. 그 대화를 2분 넘게 지나 열면 baton이 열려 있지 않은 것으로 봤습니다. 이제 프로세스 자체를
  확인합니다.
