# Phase 0 결과 — 실계정 없이 확인한 것 (2026-10-26)

**방법**: 실제 `claude.exe` 2.1.308을 로컬 가짜 Messages API(`harness/mockapi.py`)에 붙여서 실험 7개를 돌렸고,
각 실험을 다른 에이전트가 새 폴더에서 **독립적으로 다시 돌려 반박을 시도**했습니다(7개 모두 재현 완료).
인증은 더미 API 키(`apiKeyHelper`)라서, 구독(OAuth) 계정에서만 나오는 동작은 아래 "실계정 필요" 목록으로 분리했습니다.

**결론**: 설계의 핵심 루프 — *StopFailure 훅으로 한도 감지 → Ctrl+Break로 정상 종료 → 다른 프로필에서
`claude -r <대화 파일 절대경로> "<이어가기 프롬프트>"`로 재실행* — 은 사용자 입력 없이 동작합니다.
같은 세션 ID·같은 대화 파일이 유지되고, 새 계정은 한도에 걸린 질문까지 포함한 전체 대화를 받습니다.
A→B→C 연쇄 전환도 됐습니다.

## 설계에 반영할 변경점

1. **재개는 항상 대화 파일 절대경로로**: `claude -r "<transcript.jsonl>" "<이어가기 프롬프트>"`. 경로는 StopFailure 페이로드나 첫 실행 때 기억한 값을 쓰고, 작업 폴더로부터 재계산하지 않음(한글 등은 전부 `-`로 바뀌어 손실·충돌 가능).
2. **junction 공유는 선택 기능으로 미룸**: 경로 재개만으로 연속성이 확보됨. junction은 기본 `/resume` 목록을 계정 간에 공유하고 싶을 때만 쓰고, 쓸 때는 좁은 Read 허용 규칙, junction 인식 삭제, 프로필 이름 고정이 필수.
3. **대상 프로필 사전 준비**: 전환 전에 대상 프로필 `.claude.json`에 `hasCompletedOnboarding`과 현재 작업 폴더(정확한 문자열)의 신뢰를 넣음. 원본 프로필의 신뢰를 복사하고, 해당 프로필을 쓰는 claude가 없을 때만, 읽고-고치고-원자적으로 씀.
4. **훅만 주입, statusLine은 주입 안 함**. 훅은 exec 형식(`command`=런처 exe 절대경로, `args`=[...])만 사용. `args`에 `${...}` 문자열을 넣지 않음(치환됨).
5. **전환 조건**: StopFailure `error == "rate_limit"`일 때만. `server_error`(529)는 같은 계정에서 대기. 실계정 확인 전까지는 최종 실패한 `rate_limit`은 전부 전환 대상으로 봄(Claude Code가 이미 자체 재시도를 소진한 뒤이므로).
6. **종료/재실행 절차**: SessionStart 이후에만 Ctrl+Break → 종료 대기(SessionEnd 훅 시간 + 여유) → 실패 시에만 강제 종료(가급적 시작 10초 이후) → 콘솔 모드 2개 + 코드 페이지 2개 복원 + VT 초기화 → 재실행. 런처는 Ctrl+C/Ctrl+Break 핸들러로 자신을 보호.
7. **단일 작성자 보장**: 모든 프로필의 `sessions/*.json`을 확인해 같은 세션을 쓰는 프로세스가 있으면 재실행하지 않음. 프로세스 정리는 PID가 아니라 생성 시 받은 핸들로.
8. **전환 중 입력 처리**: "계정 전환 중…" 표시. 그 사이 입력은 막거나 런처가 받아서 새 화면이 뜬 뒤 다시 넣음.
9. **이어가기 프롬프트 문구**: 한도에 걸린 질문은 자동으로 다시 붙어서 가므로 반복하지 않음. 사용자 화면과 대화 기록에 그대로 보이므로 자연스러운 문장으로.
10. **화면 판별**: Windows Terminal에서는 입력 표시가 `>`가 아니라 `❯`. 화면 문자열에 의존하는 판별은 최소화.
11. **새 프로필 첫 실행 시 공식 플러그인 마켓플레이스를 내려받음**(약 15MB, 네트워크 차단 설정으로도 안 막힘) — 사용자 안내 필요.

## 실계정이 있어야 확인할 수 있는 것 (Phase 0b)

1. **실제 구독 한도 429의 모양**: 헤더(`anthropic-ratelimit-unified-*`, `x-should-retry`, `retry-after`), 재시도 여부, StopFailure가 `rate_limit`으로 오는지, "You've hit your limit · resets …" 문구. 이전 바이너리 분석으로는 구독 계정의 한도 429는 재시도하지 않는 것으로 보이지만 실측 필요.
2. **구독자용 한도 안내 창**(rate-limit 옵션 메뉴 등)이 떠서 대기 상태를 막거나 키 입력을 가로채는지.
3. **사전 전환용 신호**: OAuth에서 statusLine `rate_limits` / `rate_limit_event`가 오는지.
4. **OAuth 첫 실행**: 프로필별 로그인 화면, `.credentials.json`이 `CLAUDE_CONFIG_DIR` 안에 생기는지, 두 번째 프로필 로그인이 첫 번째를 덮지 않는지, 토큰 만료 상태에서의 재실행.
5. **다른 계정·다른 조직으로 이어받을 때 API가 이전 응답을 받아주는지**(서명된 thinking 블록, 도구 결과 등 — 가짜 서버는 이런 블록을 만들지 않음). 모델이 새 계정 요금제에서 안 될 때의 동작.
6. **전환 비용**: 새 계정이 캐시 없이 전체 대화를 다시 읽을 때 한도를 얼마나 쓰는지.
7. **실제 터미널**: Windows Terminal, 기존 콘솔 창, VS Code 터미널에서의 화면 복원과 물리 Ctrl+Break 키.

## 실험 중 사고와 조치

- e7의 정리 코드가 PID만 보고 종료하는 바람에, PID가 재사용된 **다른 실험의 테스트 프로세스**를 한 번 종료시켰습니다(e4 2번째 시도 무효, 최종 결과에는 영향 없음). 사용자 데스크톱 앱의 세션은 모두 살아 있음을 확인했고, e4·e7 정리 코드는 실행 파일 경로 + 생성 시각이 일치할 때만 종료하도록 고쳤습니다. 제품에서도 프로세스는 핸들로 관리합니다(변경점 7).
- 격리 설정에도 불구하고 새 프로필마다 공식 플러그인 마켓플레이스 다운로드가 일어났습니다(인증 정보와 무관). 실험이 완전한 오프라인은 아니었습니다.
- e7 시제품 감독 프로그램은 로그 파일을 다른 프로세스가 열고 있으면 `os.replace`가 실패해 멈추는 약점이 있었습니다(시제품 한정, 제품 구현 시 주의).

## 재현

```bash
python -I spikes/phase0/smoke.py <빈 폴더>
python -I spikes/phase0/experiments/e7_switchloop.py <빈 폴더>
```

각 실험 스크립트(`experiments/e*.py`)는 빈 폴더를 인자로 받아 JSON 보고서를 출력합니다. `verify_*.py`는 검증 단계에서 추가된 보조 실험입니다.
